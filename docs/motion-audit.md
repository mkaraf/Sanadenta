# Motion and interaction audit — open findings

Audit of animations and interactive elements (November 2026). Nothing below has been implemented yet; tick items off as they land. Companion to [design-review.md](design-review.md).

**How it was checked:** scripted interactions in headless Chrome and the in-app browser at 1440 px and at 375 px with touch emulation — running animations, element positions over time, layout shift, reduced motion, rapid menu toggling, Escape, tap outside, resizing, and JavaScript disabled. Code read: `src/assets/styles/tailwind.css`, `src/components/common/BasicScripts.astro`, and all hover/transition classes.

## Summary

Restrained and robust: layout shift measured 0, no scroll hijacking, and with `prefers-reduced-motion: reduce` nothing animates and anchor jumps are instant. Hover styles apply only on devices that can hover (Tailwind 4 wraps `hover:` in `@media (hover: hover)`), so they never stick after a tap.

What breaks the calm: the same 56 px / 1000 ms entrance on all six sections, two endless loops in the hero, and no tap feedback on touch devices (Tailwind's preflight makes the tap highlight transparent and there are no `active:` styles).

## Recommended order

1. [x] Add tap feedback to every button, row and menu item (#2).
2. [x] Remove the two hero loops (#1, #4).
3. [x] Rework the section entrance (#3, #8, #9).
4. [x] Make the mobile menu clearer: X icon, short fade and slide (#5).
5. [x] Tidy mobile menu behavior: close on tap outside, reset on resize (#6, #7).

Also resolved: #8 and #9 by the #3 rework (booking button no longer moves after the jump; old reveal script replaced). #10 kept as is by design. #11: the contact-row arrow also nudges on tap, and no longer moves at all with reduced motion. #12: every transition now uses the spec's ease-out curve `cubic-bezier(0.2, 0, 0, 1)` (theme tokens in `tailwind.css`); links and rows 150 ms, filled buttons 200 ms. #13–#15 kept as is (focus ring, sticky header, smooth scrolling).

## Additions after the audit

Three small interaction refinements, all feedback on what the visitor is doing:

- **Header on scroll** (`Header.astro`): once the page moves, `data-scrolled` adds a soft shadow and a slightly more solid background (250 ms). Height never changes, so nothing shifts.
- **Navigation underline and current section** (desktop nav): a 1 px `primary-deep` line grows from the centre on hover and keyboard focus (200 ms), and marks the section being read via `aria-current` (last section whose top passed 40% of the viewport). One passive scroll listener, one update per frame.
- **Booking arrival cue** (`Contact.astro`, `tailwind.css`): after a jump to `#contact`, the hours + booking card gets one soft gold ring (`:target`, 1.6 s, no movement). Delayed 900 ms so it peaks as the smooth scroll lands; starts at once with reduced motion. Plays once per jump; works without JavaScript.

## Motion specification

| Interaction                        | Duration                                     | Easing                                | Movement                                                                                            | Reduced motion          |
| ---------------------------------- | -------------------------------------------- | ------------------------------------- | --------------------------------------------------------------------------------------------------- | ----------------------- |
| Hover color (buttons, links, rows) | 150 ms links and rows; 200 ms filled buttons | ease-out `cubic-bezier(0.2, 0, 0, 1)` | none                                                                                                | keep (color only)       |
| Press / tap (`active:`)            | about 80 ms in, 150 ms release               | ease-out                              | buttons 1 px down plus one shade darker; rows and menu items a background tint; no scale below 0.98 | color only, no movement |
| Arrow nudge (contact rows)         | 150–200 ms                                   | ease-out                              | 4 px                                                                                                | none (already in place) |
| Mobile menu open                   | 200 ms                                       | ease-out                              | opacity 0→1, slide 8 px down                                                                        | instant                 |
| Mobile menu close                  | 140 ms (about 70% of opening)                | ease-in `cubic-bezier(0.4, 0, 1, 1)`  | reverse                                                                                             | instant                 |
| Hamburger → X icon                 | 150 ms                                       | ease-in-out                           | crossfade or line rotation, no bounce                                                               | instant swap            |
| Section/photo entrance (if kept)   | 450–550 ms; stagger at most 60 ms            | `cubic-bezier(0.22, 1, 0.36, 1)`      | 16–20 px upward; movement only, text never hidden                                                   | none                    |
| Anchor scrolling                   | native smooth scroll                         | browser default                       | —                                                                                                   | instant jump (already)  |
| Focus ring                         | 0 ms                                         | —                                     | —                                                                                                   | —                       |
| Loops                              | none                                         | —                                     | —                                                                                                   | —                       |

Rules:

- Nothing loops.
- The entrance runs once and never for content visible on load.
- Booking buttons never move after the user arrives.
- Animate only `transform`, `opacity` and colors — never size or position properties that shift layout.

## Limitations

- Touch was emulated in Chrome, not tested on real phones; iOS Safari wasn't tested.
- Smoothness was measured (positions, timings, layout shift) in headless Chrome on the dev server, not watched on a low-end device; production timings may differ slightly.
- Not tested: the external Hygessa booking page and the Google map (it didn't load in either test browser).
- One headless run looked like opening `/#contact` animated a scroll from the top; it was an in-page jump from `/`, so the smooth scroll was expected. No defect.

## Side finding (not motion)

- [x] Tailwind also scans the untracked `.claude/skills/` folder, so unrelated classes (such as `bg-blue-800`) end up in the built CSS (`dist/_astro/*.css`, 94 KB). Fixed: `.claude/` and `docs/` are excluded with `@source not` in `tailwind.css`; built CSS went from 96 KB to 61 KB (15.7 KB → 10.2 KB gzipped).
